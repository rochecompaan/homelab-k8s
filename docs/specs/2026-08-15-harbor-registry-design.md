# Harbor container registry — design

Date: 2026-08-15
Status: approved (design), pending implementation plan

## Context

Three partially-built ArgoCD apps exist for a Harbor registry, none of them
registered in `argocd/homelab/apps/kustomization.yaml`, so nothing deploys:

- `argocd/base/harbor/` — Harbor Helm chart 1.18.0 Application (sync-wave 4,
  namespace `harbor`). Broken values: truncated `externalURL`
  (`https://harbor.rochecompaan`), a mangled `secret=[REDACTED] harbor-tls`
  line, references to a CloudNativePG cluster (`harbor-rw` / secret
  `harbor-app`) and a PVC (`harbor-registry`) that do not exist, and an empty
  `ingress: {}` with `expose.type: clusterIP`.
- `argocd/base/redis-harbor/` — redis-ha chart 4.35.3 Application (sync-wave 3,
  release `harbor-redis`, no auth, 2 replicas, 2Gi longhorn volumes).
  Deployable as-is; its announce services match Harbor's external Redis config.
- `argocd/base/container-registry/` — umbrella Application (sync-wave 3)
  pointing at repo path `argocd/harbor`, which does not exist. Intended to
  deploy the supporting resources.

## Decisions (confirmed with user)

- Private exposure only: host `harbor.compaan` on the `traefik-private`
  ingress class, TLS issued by the `compaan-ca` ClusterIssuer (jellyfin
  pattern). CoreDNS already rewrites `*.compaan` to `traefik-private`, so no
  DNS work is needed.
- Registry blob storage: filesystem on a Longhorn PVC (`harbor-registry`,
  RWO). Single registry replica. No garage/S3 backend.
- Trivy vulnerability scanning stays enabled, 1 replica.
- All components run as 1 replica (homelab sizing).

## Design

### App topology

Three ArgoCD Applications, all targeting namespace `harbor`, all registered in
`argocd/homelab/apps/kustomization.yaml`:

| App                  | Wave | Role |
|----------------------|------|------|
| `container-registry` | 3    | Umbrella; path fixed from `argocd/harbor` to `argocd/homelab/harbor`; deploys supporting resources |
| `redis-harbor`       | 3    | Unchanged |
| `harbor`             | 4    | Harbor Helm chart 1.18.0 with corrected values |

The wave-3 apps reconcile before `harbor` (wave 4). Harbor's sync retry
(5 attempts, 5s backoff ×2, max 3m) covers any CloudNativePG bootstrap lag.

### New overlay `argocd/homelab/harbor/`

Deployed by the `container-registry` umbrella app:

- `harbor-cluster.yaml` — CloudNativePG `Cluster` named `harbor`: 1 instance,
  `storageClass: longhorn`, 5Gi, initdb bootstrap with database `harbor` and
  owner `harbor`. Produces service `harbor-rw` and generated secret
  `harbor-app`. CNPG app secrets contain a `password` key, which is exactly
  the key Harbor's chart requires in `database.external.existingSecret`.
- `harbor-registry-pvc.yaml` — PersistentVolumeClaim `harbor-registry`,
  `storageClass: longhorn`, `ReadWriteOnce`, 100Gi, for image blobs.
- `harbor-secrets.yaml` — SealedSecret `harbor-secrets` generated by a
  `just seal-harbor-secrets` recipe, with keys `HARBOR_ADMIN_PASSWORD`,
  `secretKey` (16 chars, replaces the chart's insecure default), `secret`,
  `CSRF_KEY`, `JOBSERVICE_SECRET`, `REGISTRY_HTTP_SECRET`, `REGISTRY_PASSWD`,
  `REGISTRY_HTPASSWD`. Pinning all of them keeps Helm renders stable, so
  ArgoCD does not see perpetual diffs (the chart randomises these per render
  by default).
- `harbor-ingress.yaml` — Ingress: `ingressClassName: traefik-private`,
  annotation `cert-manager.io/cluster-issuer: compaan-ca`, host
  `harbor.compaan`, TLS secret `harbor-compaan-tls`, backend service
  `harbor` port 80 (the chart's nginx gateway, which routes the UI, `/api/`
  and `/v2/`).
- `kustomization.yaml` — lists the four resources above.

### `argocd/base/harbor/app.yaml` value changes

- `externalURL: https://harbor.compaan`
- `expose.type: clusterIP` stays; `expose.tls.enabled: false` (traefik
  terminates TLS); the mangled `secret=[REDACTED] harbor-tls` line is deleted;
  `expose.ingress` stays empty/unused.
- Replicas set to 1 for `portal`, `core`, `jobservice`, `registry`, and
  `trivy`. Trivy stays enabled.
- Persistence: registry keeps `existingClaim: harbor-registry`; the
  chart-managed PVCs get explicit `storageClass: longhorn` and sizes:
  jobservice 1Gi, trivy 5Gi (Trivy DB cache).
- Database block unchanged (`host: harbor-rw`, port `5432`, username `harbor`,
  `coreDatabase: harbor`, `existingSecret: harbor-app`, `sslmode: disable`) —
  already matches the CNPG cluster above.
- Redis sentinel block unchanged — already matches the `harbor-redis` redis-ha
  release (no auth).
- Admin password and chart secrets via `existingSecretAdminPassword`,
  `existingSecretSecretKey`, `core.existingSecret`, `core.existingXsrfSecret`,
  `jobservice.existingSecret`, `registry.existingSecret`, and
  `registry.credentials.existingSecret` — all pointing at `harbor-secrets`.
- `updateStrategy.type: Recreate` — the chart default `RollingUpdate`
  deadlocks on RWO Longhorn volumes during upgrades.
- `notary.enabled: false` stays.

### Registration

Add to `argocd/homelab/apps/kustomization.yaml`, in alphabetical position:

- `../../base/container-registry`
- `../../base/harbor`
- `../../base/redis-harbor`

### DNS and certificates

No DNS changes: CoreDNS rewrites `*.compaan` to
`traefik-private.kube-system.svc.cluster.local`. cert-manager issues
`harbor-compaan-tls` from `compaan-ca` via the ingress annotation.

## Verification

Static configuration — no new automated tests per the repo testing policy.
Direct verification instead:

1. `kustomize build argocd/homelab/harbor` and
   `kustomize build argocd/homelab/apps` render cleanly.
2. `helm template` of chart `harbor` 1.18.0 with the exact `valuesObject`
   catches values-schema errors before pushing.
3. After merge and ArgoCD sync: all three apps Healthy;
   `curl -s https://harbor.compaan` returns the portal; `docker login
   harbor.compaan` plus a push/pull smoke test.

## Out of scope

- Public exposure / Let's Encrypt issuance.
- S3 (garage) registry storage backend.
- HA replicas for any Harbor component.
- Robot accounts, projects, and other in-Harbor configuration.
